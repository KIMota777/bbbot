# bbbot — торговые боты и сигнальный помощник для Bybit

Исследовательский проект: 5 торговых ботов (BTC/ETH/LTC/DOGE/SOL, линейные
перпетуалы, 15m) + сигнальный помощник по BTC (6 среднесрочных сетапов),
отобранные девятью волнами генетической оптимизации с walk-forward
экзаменами на 3.2 годах истории, и локальный сайт с графиками и аналитикой.

## Быстрый старт

```bash
pip install -r requirements.txt

# сайт: http://127.0.0.1:8000  (или start_site.bat на Windows)
python webapp/app.py

# бот (DRY_RUN по умолчанию — реальные ордера не отправляются)
python bot_rsi.py DOGE          # финальный конфиг монеты
python bot_rsi.py BTC bear      # архивные режимы: normal | bear | turbo

# сигнальный помощник BTC (не торгует — говорит, где входить)
python advisor.py

# новостной фон: что сейчас видят боты (нули = фон пуст, торгуют как обычно)
python news_state.py
```

Новостной фон наполняет Claude через MCP-сервер — подключение в
[docs/MCP_SETUP.md](docs/MCP_SETUP.md), правила весов в
[docs/NEWS_STRATEGY.md](docs/NEWS_STRATEGY.md).

Для реальной торговли: ключи в переменных окружения `BYBIT_API_KEY` /
`BYBIT_API_SECRET` (без права вывода средств!) и `DRY_RUN = False` в
`config.py`. Сначала обкатка в DRY_RUN.

## Структура

| Файл | Что это |
|------|---------|
| `config.py` | все конфиги ботов (финальные + архив волн), риск-менеджмент |
| `bot_rsi.py` | живой бот: RSI+сетка+уровни, фильтры, kill switch, реинвест |
| `advisor.py` | сигнальный помощник: 6 сетапов BTC, R:R 1:3, реинвест |
| `signal_engine.py` | движок сетапов: сигнал на 4ч, исполнение на 15м |
| `evolution*.py` | волны генетического отбора v1–v9 (walk-forward) |
| `patterns.py`, `smc.py` | детекторы графических паттернов и Smart Money |
| `webapp/` | сайт: боты, сигналы, PnL-кривые, эволюция, архив |
| `build_*.py` | пересчёт данных сайта после смены конфигов |
| `gridlib.py` | геометрия сетки и подвижных SL/TP — общая с движком и ботом |
| `evolution10.py` | волна v10: отбор подвижной сетки (итог — не принята) |
| `newsfeed.py` | загрузка новостей из RSS, склейка, детект монет |
| `news_state.py` | веса новостей, свёртка в index/heat, границы влияния |
| `news_mcp.py` | MCP-сервер: Claude как агрегатор новостного фона |
| `test_*.py` | проверки; главная — `test_gridlib.py` (тождественность) |

## ⛔ Важное: в движке были два дефекта, цифры пересчитаны

31.07.2026 в бэктест-движке нашлись две ошибки, обе завышали результат.

**Главная — перенос стопа в безубыток (`be_move`).** Триггер срабатывал по
ХАЮ бара, а стоп выставлялся на закрытии. Если бар успевал вернуться ниже
безубытка, стоп оказывался ВЫШЕ рынка — для лонга биржа такой ордер не
примет. Движок же спокойно «исполнял» по нему выход на следующем баре и
засчитывал прибыль, которой не было.

Это не редкий угол. За 3.2 года: у DOGE так происходило в **21%** срабатываний
(146 из 701), у LTC в **20%**, у SOL в **25%**. У BTC — ноль: там крупный тейк,
и бар почти никогда не успевает вернуться. Поэтому BTC единственный не
пострадал.

**Вторая — модель ликвидации.** Она проверялась только на свече, где задет
стоп. Но при высоком плече цена ликвидации ближе стопа: свеча могла дойти до
ликвидации, не коснувшись стопа, и движок считал позицию живой.

## ⛔ Ещё три дефекта движка, найденных аудитом 14.08.2026

Таблица выше — тоже не окончательная. Аудит нашёл, что исправление be_move внесло
**новый** оптимистичный угол, и вместе с ним ещё два искажения:

1. **Тейк в свече, где долилось колено сетки.** Движок исполнял доливку по низу свечи,
   а закрывал по тейку от средней ДО доливки — «купил на дне, продал по старой цене».
   Живой бот так не может: его тейк стоит на бирже от текущей средней и после доливки
   переезжает вниз.
2. **Тейк считался мейкерским лимитом** (комиссия 0.02%, нулевое проскальзывание), тогда
   как бот отправляет его через `set_trading_stop` — то есть рыночным ордером по тейкерской
   ставке 0.055% плюс проскальзывание.
3. **Просадка считалась только по закрытым сделкам.** Плавающий убыток внутри цикла —
   а сетка почти всегда пересиживает глубокие заходы — в метрику не попадал. Именно по
   этой метрике выбиралось ПЛЕЧО.

**Просадки выросли почти вдвое у всех.** Это главное, а не доходности: плечи x10 и x15
выбирались объективным правилом «наибольшее плечо с просадкой ≤ 20%», и по честной метрике
этому правилу больше не удовлетворяет ни DOGE, ни SOL, ни BTC.

**Три оговорки, без которых таблицу читать нельзя.**

1. **Окно другое:** прежние цифры считались по 23.07.2026, эти — по 14.08.2026, то есть
   сравнение «было/стало» не строгое.
2. **Рост BTC с +148.3% до +223.6% не объяснён** — правки движка могут делать результат
   только хуже, поэтому до прогона на одинаковом окне это число доверия не заслуживает.
3. **Итог BTC держится на горстке сделок:** без одной лучшей он +184.5%, без трёх лучших
   +120.0%. При 57 сделках за 3.2 года несколько удачных входов решают всё, и повторяемость
   такого результата ничем не подтверждена. Это не «самый надёжный бот портфеля», как
   утверждали прежние описания, а самая маленькая выборка из пяти.

### Сигнальные сетапы: не проходит ни один

Учёт в помощнике записывал исход номиналом — стоп −1.0R, тейк +3.0R, без комиссий. Честный
пересчёт той же моделью, что и в бэктесте, даёт **+2.9R / −1.15R**: безубыточный винрейт не
25%, а 28.4%. Вход брался по закрытию 4ч-бара — цене, по которой войти уже физически нельзя.
После исправления **ни один из шести сетапов приёмку не проходит**, включая оба ранее
включённых на плече x20. `pump_short` отваливается даже по старому правилу на сегодняшних
данных (средний OOS −2.58 против записанных в файле +3.02).

### Протокол отбора: утечка walk-forward закрыта, но конфиги не переотобраны

Кандидаты оценивались на всех трёх экзаменационных окнах, включая те, что лежали внутри их
собственной обучающей выборки, а победитель выбирался по тому же числу, по которому потом
шла приёмка. Теперь кандидат экзаменуется только на окнах строго после своего обучения
(инструментированный прогон: 0 пересечений против 6 из 18 в старой схеме), а ворота риска
считаются на том плече, которым торгуют, а не на x5.

**Существующие боевые конфиги отбирались по старой схеме и этими правками не
реабилитируются.** Чтобы получить честные конфиги, нужен полный переотбор — это часы счёта.

**Переотбор ([`evolution11.py`](evolution11.py), прежний набор генов) прибыли
не нашёл. Волна v12 ([`evolution12.py`](evolution12.py)) расширила пространство

индикаторы), гены подвижной сетки v10 и анти-вырожденный fitness (без него GA
находил «оптимум» — не торговать вовсе). Итог по предзаданным правилам приёмки:**

- **LTC — ПРИНЯТ новый конфиг v12: +99.7% | DD 17.4% | WR 84.8% | 521 сделка.**
  Все три walk-forward-экзамена в плюсе (+10.92/+6.54/+0.79). Показательно:
  отбор сам выключил be_move — механизм, на нечестной версии которого
  держались старые цифры — и взял гены подвижной сетки (веса колен от

- SOL: лучший кандидат +80.4% (x10, DD 19.3%), но свежий экзамен −0.87 —

- DOGE: прибыльного кандидата нет (−4.2% лучший).

**Вывод: на реальные деньги можно рассматривать BTC, ETH и LTC (v12).**
DOGE и SOL — нельзя, пока их кандидаты не пройдут экзамены.

## Волна v10: подвижная сетка — реализована, отбор не приняла

Механизм подвижной сетки и подвижных SL/TP написан целиком и лежит в
[`gridlib.py`](gridlib.py) (общий источник истины для живого бота и бэктеста):
шаг и веса колен от волатильности, раскладка колен по пути до стопа,
перевыставление неисполненных лимиток, трейлинг-стоп, тейк от волатильности.

Отбор [`evolution10.py`](evolution10.py) шёл узко: боевой конфиг **заморожен**,
искались только новые гены — тогда выигрыш нельзя списать на перетюн RSI.
Правило принятия задано до прогона и жёстче обычного: отрыв по OOS > 0.5,
ни один из трёх экзаменов не ниже базы, итог за 3.2 года не ниже базового,
просадка не выше базовой более чем на 5%, доля убыточных сделок не аномально
низкая.

**Итог: ни одна монета не принята.**

| Монета | База | Лучший кандидат | Почему не принят |
|---|---|---|---|
| DOGE x10 | +133.5% / DD 18.7% | +111.8% / DD 21.2% | хуже базы и по доходу, и по просадке, и на одном экзамене |
| LTC x5 | +112.7% / DD 17.0% | тот же | генетика не нашла ничего лучше выключенной адаптации |
| BTC x15 | +148.3% / DD 9.5% | +163.3% / DD 8.1% | лучше по обоим, но отрыв по OOS +0.32 при пороге 0.5 |
| ETH x5 | +24.1% / DD 21.8% | тот же | как у LTC |
| SOL x5 | +44.0% / DD 18.6% | тот же | как у LTC |

BTC — единственный близкий случай: он лучше базы и по доходу, и по просадке,
но на экзаменах отрыв втрое меньше порога, а один из трёх фолдов ровно нулевой.
Порог задан до прогона и снижать его под результат я не стал — именно так
получаются красивые бэктесты, которые не работают вживую.

Поэтому в `config.py` гены v10 не прописаны: отсутствие ключа = прежнее
поведение, **побайтово то же самое** — это не обещание, а проверка
([`test_gridlib.py`](test_gridlib.py), 178 утверждений, включая сверку списка
сделок на всех пяти боевых конфигах).

Что удалось понять по дороге:

- **Колена по пути до стопа (`grid_mode=1`) проигрывают.** Причина
  экономическая: движок и так доливает все колена выше стопа, то есть на
  стопе маржа уже полная. Разносить колена шире — значит перекладывать
  маржу с прибыльных циклов на убыточные.
- **Трейлинг-стоп чуть не дал ложный результат.** Первый прогон показал LTC
  **+552% при просадке 2.1%** — и это оказалось дырой в моей же реализации:
  стоп считался по хаю бара, а выход засчитывался по этой цене уже на
  следующем баре, хотя рынок побывал там до того, как стоп туда попал. После
  ограничения «стоп не выгоднее закрытия бара» тот же геном даёт **+1.89%
  при просадке 25.1%**. Дыра закрыта, на неё есть регрессионный тест.
- **Экзамены раньше считались не на том плече.** OOS-фолды шли на x5, а
  деньги — на боевом плече (x15 у BTC), из-за чего порог отрыва применялся к
  втрое меньшей шкале. Исправлено; после этого BTC стал ближе всех к принятию.

## Ключевые принципы

- **Честный бэктест-движок**: комиссии тейкер/мейкер, funding, проскальзывание,
  реальный порядок исполнения внутри свечи, ликвидации.
- **Walk-forward отбор**: каждый конфиг сдавал экзамены на данных, которых
  эволюция не видела; проваленные гипотезы честно задокументированы
  (классические паттерны, SMC, Fear&Greed — не прошли).
- **Реинвест**: маржа = 25% текущего капитала, не фикс.
- **Новости — только тормоз, никогда не газ**: фон умеет запретить вход,
  подтянуть стоп и сдвинуть тейк в жёстких клампах. Открыть позицию, поднять
  плечо или раздвинуть стоп он не может ни при каких значениях — текст новости
  недоверенный вход. Оговорка по факту: механизм реализован и оттестирован, но
  **к торговле не подключён ни у одного бота** — спотового бота в проекте нет.
  Замер стоимости ошибки жил в `news_stress.py`, который удалён вместе с
  волной v10; его числа считались дефектным движком и заново не проверялись.
- Бэктест ≠ будущее. Все цифры — симуляция; сначала DRY_RUN, потом деньги,
  которые не жалко.

⚠ Не финансовый совет. Торговля с плечом — риск полной потери средств.
