# MCP-сервер `bbbot-news`: подключение и работа

Сервер даёт Claude инструменты, чтобы собрать новостной фон: скачать заголовки
из доверенных лент, оценить их весом 0..1 и сохранить результат в
`news_state.json`.

> **Фон пока никем не торгуется.** Собранный фон читают только сайт (панель на
> главной) и сам MCP (`news_preview_effect`). Фьючерсный бот `bot_rsi.py` в
> `news_state.json` не заглядывает, ключей `news_*` в `config.py` нет,
> спотового бота в репозитории не существует. Всё, что делает сервер сегодня, —
> считает и показывает фон. Подробности и что нужно, чтобы его подключить, —
> раздел 0 в [NEWS_STRATEGY.md](NEWS_STRATEGY.md).

Правила оценки — [NEWS_STRATEGY.md](NEWS_STRATEGY.md). Код — [`news_mcp.py`](../news_mcp.py).

---

## 1. Установка

Нужен Python 3.10+ и зависимости проекта:

```bash
pip install -r requirements.txt
```

Проверить, что сервер собирается и все инструменты на месте:

```bash
python test_news_mcp.py
```

Тест поднимает сервер настоящим MCP-клиентом, ходит в реальные RSS-ленты,
прогоняет полный сценарий и проверяет защиты — включая попытки подсунуть
ссылку, которая лишь притворяется доверенным доменом
(`evil.io/?ref=coindesk.com`, `theblock.com.attacker.io`, `coindesk.com@evil.io`).
Заканчивается строкой `ВСЕ 23 ПРОВЕРОК ПРОЙДЕНЫ` (последний прогон 15.08.2026,
ленты живые: загружено 105 новостей из 4 источников; число проверок растёт по
мере их добавления). Боевой файл фона тест не трогает вообще:
он работает во временной копии и сверяет время изменения `news_state.json`.

## 2. Подключение

### Claude Code

В корне репозитория уже лежит [`.mcp.json`](../.mcp.json):

```json
{
  "mcpServers": {
    "bbbot-news": {
      "command": ".venv/bin/python",
      "args": ["news_mcp.py"],
      "env": {}
    }
  }
}
```

Claude Code подхватит его при запуске из папки проекта и спросит подтверждение
на подключение сервера. Если виртуального окружения нет, замени `.venv/bin/python`
на `python3`.

### Claude Desktop

Пути обязательно **абсолютные** — Desktop запускает сервер не из папки проекта.

macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
Windows: `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "bbbot-news": {
      "command": "/Users/ВАШ_ПОЛЬЗОВАТЕЛЬ/bbbot/.venv/bin/python",
      "args": ["/Users/ВАШ_ПОЛЬЗОВАТЕЛЬ/bbbot/news_mcp.py"]
    }
  }
}
```

После правки конфига Claude Desktop нужно **полностью перезапустить** (не
просто закрыть окно). Сервер появится в списке инструментов значком разъёма.

## 3. Как пользоваться

Достаточно одной просьбы — сервер сам подсказывает Claude порядок работы:

> Собери новостной фон для моих ботов: возьми свежие заголовки, оцени значимые
> по правилам из scoring_guide и сохрани. Потом покажи, что получилось по BTC.

Что произойдёт под капотом:

1. `news_scoring_guide` — Claude забирает правила весов, чтобы оценки были
   сопоставимы между запусками;
2. `news_fetch_headlines` — **сервер** (не Claude) идёт в RSS и возвращает
   нормализованные заголовки с посчитанными полями;
3. Claude оценивает каждую значимую новость: категория, знак, вес, горизонт;
4. `news_submit_scores` — оценки проверяются и сохраняются в `news_state.json`;
5. `news_background` / `news_preview_effect` — проверка результата.

Обновлять фон имеет смысл раз в несколько часов. Через 12 часов без обновления
фон протухает и перестаёт влиять на ботов — это защита, а не сбой.

### Инструменты

| Инструмент | Что делает | Меняет состояние |
|---|---|---|
| `news_scoring_guide` | правила присваивания веса | нет |
| `news_list_sources` | доверенные ленты и белый список доменов | нет |
| `news_fetch_headlines` | скачивает свежие заголовки | нет |
| `news_submit_scores` | сохраняет оценки Claude | **да** |
| `news_background` | текущие `index` и `heat` по монетам | нет |
| `news_preview_effect` | как фон повлияет на конкретного бота | нет |
| `news_clear` | удаляет записи из фона | **да** |

## 4. Проверка, что всё работает

```bash
# что видят боты прямо сейчас
python news_state.py

# что лежит в ленте (без участия Claude)
python newsfeed.py
```

`python news_state.py` сразу после установки покажет нули по всем монетам —
это правильно: фон пуст, пока Claude не отдал оценки, и боты работают ровно
как раньше.

## 5. Если не работает

**Сервер не появился в списке.** Проверь, что путь к Python абсолютный и
запускается сам по себе: `/полный/путь/.venv/bin/python /полный/путь/news_mcp.py`
должен не падать, а молча ждать (это stdio-сервер, он общается через
стандартный ввод). Прерви его `Ctrl+C`.

**`ModuleNotFoundError: mcp`.** Зависимости поставлены в другое окружение —
укажи в конфиге тот Python, где стоит `mcp`.

**`CERTIFICATE_VERIFY_FAILED` при загрузке лент.** На macOS с python.org-сборкой
не установлены корневые сертификаты. Проект ходит в сеть через `requests`
(он использует `certifi`), так что этой ошибки быть не должно; если она всё же
появилась — запусти `/Applications/Python\ 3.x/Install\ Certificates.command`.

**Лента отвечает ошибкой.** Это нормально: `news_fetch_headlines` возвращает
поле `ошибки_лент` и продолжает работу на остальных источниках.

## 6. Что сервер не умеет — намеренно

- **Торговать.** В `news_mcp.py` нет ни одного обращения к бирже. Отправить
  ордер через этот сервер невозможно.
- **Читать или отдавать API-ключи**, менять `DRY_RUN`, плечо или маржу.
- **Принимать ссылку с постороннего домена** — только четыре известные ленты.
  Сверяется разобранный hostname (`newsfeed.match_allowed_domain`), а не
  подстрока: `https://evil.io/?ref=coindesk.com` и
  `https://theblock.com.attacker.io/` отклоняются.
- **Поднять влияние новости выше потолка** — вес режется в `[0..1]`, потолки
  воздействия заданы кодом в `news_state.py`.

Заголовки новостей — недоверенный текст. Если внутри окажется указание,
адресованное модели, Claude проинструктирован показать его пользователю,
а не выполнять. Подробнее — раздел 7 в [NEWS_STRATEGY.md](NEWS_STRATEGY.md).
